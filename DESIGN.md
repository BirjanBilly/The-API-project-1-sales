# Design Description

## Product objective

Reduce the time a roofing-distributor sales representative spends researching accounts before account planning. The system pre-generates a ranked, evidence-grounded lead queue and recommends a next action without replacing the representative's judgement.

## Architecture

```text
Verified GAF seed data
        |
        v
CSV ingestion and normalisation
        |
        v
SQLite / PostgreSQL-compatible relational model
        |
        +----> Perplexity Search API ----> public evidence table
        |
        +----> OpenAI structured output -> insight + contact candidates
        |
        +----> deterministic lead score
        |
        v
Streamlit review interface
```

## Why the pipeline is not centred on scraping

The GAF page is dynamic and automated collection may be brittle or restricted by site terms. The optional Playwright helper assists with visible profile-link collection but requires the user to perform the search and review every extracted row.

In production, data acquisition should use an approved API, licensed dataset, partnership, or explicitly authorised collector.

## Data model

- `companies`: stable company identity and public GAF facts;
- `evidence`: every web source supplied to the model;
- `contacts`: only publicly supported decision-maker candidates;
- `insights`: structured account-planning brief and evidence hash;
- `lead_reviews`: representative assignment, notes and workflow status;
- `pipeline_runs`: operational success and failure history.

## Reliability controls

- idempotent CSV upsert using GAF URL or normalised name/postal code;
- bounded HTTP retries;
- schema-constrained OpenAI output using Pydantic;
- source-URL allowlist applied after generation;
- no guessed decision-makers or emails;
- evidence hashing avoids unnecessary regeneration;
- one failed lead does not terminate the complete batch;
- low-confidence deterministic fallback for demonstrations without API keys.

## Lead scoring

The score is deterministic and explainable rather than generated by the LLM:

- GAF certification or award: 25;
- territory proximity: 15;
- public rating/review strength: 10;
- contact/profile completeness: 10;
- public recent-activity signals: 15;
- supported decision-maker confidence: 15;
- supported product-fit confidence: 10.

The UI displays the component values so a representative can challenge the ranking.

## Scalability path

1. Replace SQLite with managed PostgreSQL and schema migrations.
2. Separate the Streamlit demo from a FastAPI application service.
3. Put research and AI enrichment into a queue with worker concurrency limits.
4. Partition work by tenant, territory and representative.
5. Use idempotency keys for ingestion and generation jobs.
6. Add a secret manager, authentication, RBAC and row-level access.
7. Add traces, cost, latency, retry, freshness and quality dashboards.
8. Introduce dead-letter queues and operator replay tools.
9. Evaluate output on a labelled set before release.

## Deliberate omissions

- no automatic cold-email sending;
- no guessed personal data;
- no unsupported revenue estimates;
- no attempt to bypass site controls;
- no claim that the prototype is production-ready.
